## Phase 2 — 데이터 전처리 및 통합

### 2.1 목표
서로 다른 출처(HIRA·KOSIS·행정안전부)의 12+ 개 원본 파일을 단일 **마스터 데이터셋**(`master_dataset.csv`)으로 합치는 것. 단위·표기·연도가 제각각이라 정합성 확보가 가장 큰 과제.

### 2.2 표준 키 설계
모든 데이터셋을 다음 두 키로 통일:

- `sido` (시·도): "서울특별시", "강원특별자치도" 등 **풀네임**으로 통일
- `sgg` (시·군·구): "강남구", "강릉시" 등 한글 그대로

> 명세서는 5자리 법정동 코드(예: 11110 = 서울 종로구)를 표준으로 제안했으나, **실제 데이터에 코드가 없는 파일이 많고 한글 명만 있는 경우가 대부분**이라 한글 명을 조인 키로 채택. 매칭 신뢰성은 검증 단계(2.6)에서 검증.

### 2.3 시도명 정규화 (loader.py의 `SIDO_FULL`)
각 데이터 출처마다 시도 표기가 다르다.

| 표기 예 | 출처 |
|---|---|
| "서울" | HIRA 02_specialists, 진료현황 |
| "서울특별시" | KOSIS 미충족의료율, 복지수급자, 인구 |
| "강원" / "강원도" / "강원특별자치도" | 데이터마다 다름 |

→ **풀네임 매핑 딕셔너리**(`SIDO_FULL`)로 모두 "서울특별시", "강원특별자치도" 같은 풀네임으로 통일하는 `normalize_sido()` 함수.

### 2.4 시·군·구 표기 정규화 (`_normalize_one_sgg`) — Try & Error 다수

원본 데이터의 시·군·구 표기 불일치가 분석의 가장 큰 걸림돌이었다.

#### 발견된 4가지 불일치 패턴

**(1) 광역시 일반구 — 시도 prefix가 sgg 앞에 붙음**
HIRA `01_facilities` 데이터는 "대구중구", "광주북구"처럼 시도명이 prefix로 붙어 있다. 인구 데이터는 그냥 "중구", "북구".
→ 정규화에서 시도 prefix를 제거.

```python
short = {"서울특별시": "서울", "부산광역시": "부산", ...}
if sgg.startswith(short[sido]): sgg = sgg[len(short):]
```

**(2) 부산진구 예외**
"부산"이 시도 prefix와 겹치는 행정구 이름. (1) 규칙을 그대로 적용하면 "부산진구"가 "진구"로 잘못 벗겨짐 → 매칭 실패.
→ 예외 처리 추가: `if not (sido == "부산광역시" and sgg == "부산진구")`

**(3) 특례시 일반구 — 인구 데이터는 시 단위, 다른 데이터는 구 단위**

| 원본 데이터 | 표기 |
|---|---|
| 인구 (KOSIS) | "수원시" 단일 |
| 의료급여(복지수급자) | "수원시권선구", "수원시영통구" (공백 없음) |
| 진료현황 (KOSIS) | "수원시 권선구", "수원시 영통구" (공백 있음) |
| HIRA facilities | "수원권선구" ("시" 없음) |

→ "수원·고양·성남·부천·안산·안양·용인·창원·포항·전주·천안·청주·화성" 13개 도시는 **구 단위 행을 시 단위로 sum 집계**해서 인구 데이터 키에 맞춤.

**(4) 세종특별자치시 단일 단위**
세종은 시·군·구가 없는 단일 행정 단위. 데이터마다 sgg='소계' 또는 sgg='세종시' 등 다양하게 표기.
→ `sgg='세종특별자치시'`로 통일하는 특별 케이스.

### 2.6 KOSIS의 .xls가 사실 HTML/XML이었던 문제 (Try & Error)

KOSIS에서 내려받은 인구 파일 `101_DT_1B04005N_*.xls`는 확장자가 `.xls`지만 실제로는 SpreadsheetML 2003 XML(엑셀 호환 XML 포맷).
- `pd.read_excel`: 실패 (binary xls 아님)
- `pd.read_html`: 실패 (단순 HTML 테이블 아님)
- 해결: **`lxml`로 직접 XML 파싱** (`_parse_kosis_spreadsheetml`). namespace `urn:schemas-microsoft-com:office:spreadsheet` 사용, Row/Cell/Data 노드 순회.

### 2.8 HIRA 시·도 단위 데이터의 시·군·구 분배

> 본 프로젝트의 가장 큰 데이터 구조적 도전. 사용자와 합의한 절충안.

**문제**: HIRA의 의사·간호사·전문의·장비·특수진료실은 시·도(17개) 단위만 공개. 시·군·구 분석에 그대로 쓸 수 없음.

**해결책 (사용자 결정)**: 시·도 합계를 **인구 비례로 시·군·구에 분배**.

```
시·군·구 i의 값 = 시·도 합계 × (시·군·구 i 인구 / 시·도 인구)
```

이렇게 분배한 뒤 per-100k(인구 10만 명당) 표준화를 적용하면, 같은 시·도 내 시·군·구는 모두 동일한 per-100k 값을 갖게 된다(수학적 항등식). 즉 **시·군·구 변별력이 시·도 평균에 종속**되는 한계가 발생하지만, 시·군·구 단위 분석의 외형(229 시·군·구 단위 마스터)은 유지된다. Phase 3에서 WAI에 그대로 영향을 미친다.

`preprocess.py`의 `_distribute_sido()` 함수가 이 분배 로직 담당.

## Phase 3 — WAI · IAI · DPI 하위 지수 산출

### 3.1 무엇을 했나
세 가지 측면을 각각 하나의 점수(0~100)로 압축했다.

| 지수 | 의미 | 입력 변수 |
|---|---|---|
| **WAI** Workforce Adequacy Index | 의료 **인력** 적정성 | 전문의·간호사·5개 진료과 전문의(내과·외과·응급·소아·산부) — 모두 **인구 10만 명당**(per-100k) 환산 |
| **IAI** Infrastructure Adequacy Index | 의료 **인프라** 적정성 | 의원·병원·종합·상급종합·보건소·보건의료원·수술실/분만실 병상·CT·MRI (per-100k) |
| **DPI** Demand Pressure Index | 의료 **수요** 압력 | 고령화율·소멸지수의 역수·기초의료급여 수급률·인당 진료비 |

산출 절차는 세 지수 모두 동일하다:

1. 각 변수를 `StandardScaler`(표준화: 평균 0, 표준편차 1로 맞추어 단위 차이 제거)로 변환
2. `PCA`(주성분분석: 여러 변수를 가장 변동이 큰 한 축으로 압축하는 기법)로 첫 번째 주성분(PC1) 추출
3. PC1의 부호를 직관에 맞추어 정렬 (예: WAI라면 의사 수와 같은 방향이 되도록)
4. 0~100으로 Min-Max 정규화 (가장 낮은 시군구 = 0, 가장 높은 = 100)

### 3.2 결과
| 지수 | PC1 설명분산 | 해석 |
|---|---|---|
| WAI | **78.5%** | 매우 강함 — 인력 변수들이 한 방향으로 잘 묶임 |
| IAI | **33.3%** | 약함 — 시·군·구 단위 시설(facilities)과 시·도 단위 장비가 같은 방향으로 안 묶임 |
| DPI | **80.5%** | 매우 강함 — 고령화·빈곤·진료비가 같은 방향 |

> **설명분산(explained variance)**: 원래 변수들의 변동(차이)의 몇 %가 PC1 하나로 설명되는지. 50% 이상이면 압축이 잘 됐다고 본다.

### 3.3 Face Validity (직관 검증)
- **WAI TOP**: 서울 강남·용산·서초·구로·동작 → 대형병원 밀집지 ✓
- **WAI BOTTOM**: 충북 영동·옥천·괴산·단양·충주 → 비수도권 변두리 ✓
- **DPI TOP**: 경북 의성·전남 고흥·경남 합천·대구 군위 → 농촌 고령지 ✓
- **DPI BOTTOM**: 경기 화성·세종·과천·대전 유성·경기 오산 → 신도시 ✓

직관과 거의 완벽히 일치.

### 3.4 알게 된 한계
WAI는 같은 시·도 내 시·군·구가 사실상 동일한 값을 가진다. HIRA(건강보험심사평가원) 데이터가 **시·도 단위만 공개되어** 인구 비례로 시·군·구에 분배했기 때문. 즉 서울 25개 자치구의 WAI는 거의 같다. → Phase 4 모델 fit에 영향을 미칠 것이라 예상.

## Phase 4 — HRI 모델 (Try & Error)

### 4.1 모델 구조
$$
\text{HRI}_i = w_{wai}\,\text{WAI}_i + w_{iai}\,\text{IAI}_i - w_{dpi}\,\text{DPI}_i
$$

가중치 $(w_{wai}, w_{iai}, w_{dpi})$는 **LASSO**(라쏘 회귀: 영향이 작은 변수의 계수를 자동으로 0으로 만들어 변수 선택을 동시에 하는 회귀 기법) 5-fold CV(교차검증: 데이터를 5등분해서 4등분으로 학습·1등분으로 검증을 5번 반복)로 추정한 회귀계수의 절대값 비율.

### 4.2 Try 1 — 종속변수 `unmet_std_pct` (미충족의료율, 옵션 B)

> **종속변수(target)**: 모델이 예측하려는 대상 변수. 여기서는 "이 지역의 의료 자원으로 미충족의료율을 얼마나 설명할 수 있는가"를 묻는 것.

| 지표 | 값 |
|---|---|
| In-sample R² (설명력: 모델이 데이터 변동의 몇 %를 설명) | **0.015** |
| Holdout R² (80:20 학습·검증 분할 후 검증셋 성능) | **−0.04** (평균 예측보다 나쁨) |
| LASSO α (정규화 강도) | 3.62 (매우 강함) |
| Raw 계수 | wai = −0.008, iai = −0.001, **dpi = 0.0** (LASSO가 DPI 완전 dropping) |
| 정규화 가중치 | w_wai = 0.87, w_iai = 0.13, w_dpi = **0** |

**부트스트랩(bootstrap: 데이터를 무작위로 다시 뽑아 100회 추정해서 신뢰구간을 보는 방법) 95% CI**:
- w_wai: [0, 1] (전 구간 — 매우 불안정)
- w_iai: [0, 0.99]
- w_dpi: [0, 0.55]

**진단**:
1. 미충족의료율은 지역사회건강조사 자기보고 데이터 → 응답 표본이 시·군·구당 800~1,500명 수준이라 잡음이 크다
2. WAI의 시·도 평탄화 한계로 시·군·구별 변별력 부족
3. **모델 신뢰도 매우 낮음** — 다른 종속변수가 필요하다고 판단

### 4.3 Try 2 — 종속변수 교체: `outflow_cost_ratio` (관외이용률, 옵션 A)

KOSIS 거주지 기준 진료현황의 **관외 진료비 / (관내 + 관외 진료비)**. 의료자원이 풍부할수록 자기 동네에서 진료를 받으니 이 비율이 낮아진다는 직관.

| 지표 | 옵션 B (Try 1) | **옵션 A (Try 2)** | 비고 |
|---|---|---|---|
| In-sample R² | 0.015 | **0.272** | 약 18배 개선 |
| 학습셋(n=183) in-sample R² | 0.023 | 0.287 | 코드의 `r2_cv` 키는 이름과 달리 in-sample 값 |
| Holdout test R² | −0.04 | **0.127** | 평균보다 명확히 우수 |
| LASSO α | 3.62 | **0.024** | 약한 정규화 → 변수 살아남음 |
| 가중치 (w_wai, w_iai, w_dpi) | (0.87, 0.13, **0**) | **(0.236, 0.407, 0.357)** | 균형 잡힘 |
| 부트스트랩 CI (w_iai) | [0, 0.99] | **[0.28, 0.49]** | 신뢰구간 좁아짐 |

**Raw 계수 부호**
- IAI → outflow: **−0.0032** (인프라↑ → 관외이용↓, 직관 ✓)
- DPI → outflow: **+0.0028** (수요압력↑ → 관외이용↑, 직관 ✓)
- WAI → outflow: +0.0019 (양수, 직관 반대) — 시·도 평탄화로 인한 가짜 상관(spurious correlation)

명세서 표준 공식대로 `HRI = w_wai·WAI + w_iai·IAI − w_dpi·DPI` 부호 유지.

### 4.4 HRI Face Validity
- **TOP 10**: 서울 강남·서초·종로·송파·마포·중구·광진·영등포·강동 + 대구 중구 (도심·거점) ✓
- **BOTTOM 10**: 경북 의성·영덕·청송·청도·영양·봉화·성주·고령 + 충남 서천·부여 (농촌·고령) ✓

### 4.5 외부 검증 (다른 지표와의 상관)
| 외부 지표 | Pearson | Spearman |
|---|---|---|
| 미충족의료율 (표준화) | −0.130 | −0.112 |
| 미충족의료율 (조율) | −0.104 | −0.117 |
| 관외이용률 (환자수 기준, 같은 데이터 다른 분모) | −0.137 | −0.232 |

전부 음의 상관 → HRI↑일수록 미충족·관외이용 모두 ↓ (방향 일관). 절대값은 약하지만 부호는 안정.

### 4.6 Robustness Check (강건성 검증)
옵션 B를 메인으로 재추정해도 결과가 일관되는지 보는 것. R² 0.015로 여전히 약해, **옵션 A 채택이 정당화됨**.

## Phase 5 — 지역 유형 클러스터링

### 5.1 무엇을 했나
WAI/IAI/DPI 세 점수의 3차원 공간에서 시·군·구를 비슷한 그룹으로 묶었다.

방법: **K-Means**(K개 중심점으로 데이터를 가장 가까운 중심에 할당, 중심을 반복 갱신)와 **Ward 계층군집**(가까운 점부터 합쳐가는 방식)을 둘 다 돌려서 교차 검증.

### 5.2 최적 K 진단

| K | SSE↓ | Silhouette↑ | Ward ARI↑ |
|---|---|---|---|
| **3** | 179.4 | **0.474** | 0.651 |
| 4 | 146.8 | 0.442 | 0.564 |
| 5 | 122.9 | 0.414 | 0.528 |
| 6 | 101.2 | 0.383 | 0.641 |
| 7 | 89.6 | 0.386 | 0.646 |
| 8 | 77.9 | 0.385 | 0.699 |

> - **SSE** (Sum of Squared Errors): 클러스터 내부 데이터가 중심점에서 떨어진 거리의 제곱합. 작을수록 잘 뭉침.
> - **Silhouette score** (실루엣 점수, −1~1): 0.5 이상이면 잘 나뉜 편. 0.474는 양호.
> - **ARI** (Adjusted Rand Index, 0~1): K-Means 결과와 Ward 결과가 얼마나 비슷한지. 두 방법이 같은 답을 내면 신뢰도 ↑.

→ **K=3**이 silhouette + ARI 모두 합리적. 자연스러운 분할.

## Phase 6 — 정책 시나리오 시뮬레이션 (3차례 수정)

### 6.1 시나리오 정의
| ID | 개입 | 대상 시·군·구 |
|---|---|---|
| S1 | 필수 5과 전문의 + 의사 전문의 **+10%** | WAI 하위 30% |
| S2 | 의원(facilities_clinic) **+5개** | IAI 하위 30% |
| S3 | CT·MRI 각 **+1대** | CT+MRI 인구당 보유량 하위 30% |
| S4 | 공공보건의료원 **+1개** | 공공보건의료원 인구당 보유량 하위 30% |

ΔHRI(개입 후 HRI − 개입 전 HRI)를 클러스터별로 비교.

### 6.2 Try 1 — 첫 시뮬레이션 결과가 이상함
**관찰된 문제**:
- S1·S2: `treated count = 227` (전체!) — 하위 30%만 적용해야 하는데 거의 모두 포함
- S1·S2 ΔHRI **음수** — 자원을 늘렸는데 복원 지수가 떨어지는 모순
- S3 ΔHRI **+22.3** — 비현실적으로 큰 변동
- S4 ΔHRI **+0.0** (treated=0)

### 6.3 진단
세 가지 버그를 발견:

#### (1) PCA를 시뮬레이션 후 다시 학습
`compute_wai/iai/dpi`는 매번 PCA를 새로 fit한다. 변수 일부만 바꿔도 새 데이터로 PCA를 다시 학습하니 PC1 축 자체가 회전해버려, 안 바뀐 시·군·구의 점수도 흔들림 → ΔHRI가 전 시·군·구에서 발생.

#### (2) HRI 0~100 정규화 분모가 바뀜
`compute_hri`가 매번 raw HRI의 min/max로 다시 정규화. 시뮬레이션 후 raw 범위가 [a, b] → [a, b + Δ]로 늘어나면, 안 바뀐 시·군·구도 `(raw − a)/(b+Δ − a)`로 분모가 커지면서 점수가 변함.

#### (3) 마스크 `<= quantile(0.30)` + 시도 평탄화
WAI 값이 시·도 단위로만 다르니 distinct 값이 17개. `<=` 비교 + 동률이 많아 quantile 임계점이 매우 높게 잡혀 거의 모두 포함.

#### (4) 공공보건의료원 quantile(0.30) = 0
대부분 시·군·구가 공공보건의료원 0개 → `< 0` 마스크에서 아무도 안 잡힘.

### 6.4 Try 2 — fit/transform 분리
**indices.py**에 `IndexFit` 데이터클래스 신설:
- baseline에서 `StandardScaler`, `PCA`, 부호, min/max를 **fit**해서 저장
- 시뮬레이션 후에는 그 객체로 `transform`만 적용 → PC1 축 고정

함수 `fit_indices(df) → (df, fits)`와 `transform_indices(df, fits) → df`로 분리.

→ 결과: treated 수는 정상 분포가 됐지만, **ΔHRI는 여전히 음수**. 정규화 분모 문제(2)가 남았기 때문.

### 6.5 Try 3 — compute_hri의 baseline_min/max 인자 추가
```python
def compute_hri(df, w, baseline_min=None, baseline_max=None):
    raw = w_wai·WAI + w_iai·IAI − w_dpi·DPI
    rmin = baseline_min ?? raw.min()
    rmax = baseline_max ?? raw.max()
    return ((raw - rmin) / (rmax - rmin)) * 100
```

baseline의 raw 범위를 저장해서 시뮬레이션 후에도 동일 분모로 정규화. **마스크 비교도 strict `<` 로 변경**.

(`reports/simulation.txt`의 최종 출력 기준)

클러스터 평균 ΔHRI (`data/processed/scenario_cluster_matrix.csv`):

## 한계점

### 데이터 자체의 한계
1. **HIRA 인력·시설·장비 데이터가 시·도 단위만 공개** → 인구비례로 시·군·구 분배. 같은 시·도 내 시·군·구는 동일한 per-100k 값을 가져 **WAI/IAI 변별력이 시·도 평균에 종속**. 강남구와 강북구의 WAI가 사실상 같아지는 문제.
2. **사망원인 통계도 시·도 단위만** → OECD 표준 치료가능사망률을 시·군·구로 외부 검증 불가능.
3. **미충족의료율 응답 표본 작음** (시·군·구당 800~1,500명) → 노이즈가 커 종속변수로 부적합.
4. **HIRA 청구 데이터에 상병코드 없음** → 만성질환·암 등 질환별 분해 불가. 단순 진료비 총량으로 대체.

### 모델·방법론의 한계
5. **횡단면 분석 (2024년 단일 시점)** → 시계열 변동·정책 도입 전후 비교 불가.
6. **인과관계가 아닌 상관관계**. HRI 높은 지역과 관외이용 낮은 지역이 관련 있다는 것만 보임. 자원 투입이 결과를 인과적으로 개선한다는 결론은 별도 자연실험(natural experiment)·DID(Difference-in-Differences) 분석이 필요.
7. **R²의 의미**: HRI 3개 지수는 학습 데이터에서 관외이용률 변동의 약 27%를, 처음 보는 데이터(holdout)에서는 약 13%를 설명한다. 나머지는 다른 요인(교통 접근성, 환자 선호, 의료기관 평판 등) 때문. 모델이 완벽한 예측 도구가 아니라 **자원 분포의 정량 지수**로 봐야 한다.
8. **WAI 계수 부호가 직관과 반대**: LASSO 회귀에서 WAI → 관외이용 = +0.0019 (양수). 시·도 평탄화의 가짜 상관. 명세 공식상 `+w_wai`로 유지했으나 해석 시 주의.
9. **클러스터 3개의 분류력**: Silhouette 0.474는 양호하나 0.7 이상은 아님. 일부 시·군·구는 경계에 걸침.

### 행정·운영적 한계
10. **행정구역 개편 패치를 코드에 하드코딩**: 군위군·청원군·인천 남구 같은 변경을 매번 손으로 매핑. 미래 개편(예: 부산 일부 통합 논의) 시 다시 패치 필요.
11. **GeoJSON 2013 버전 사용** — 최신 행정경계와 일부 차이.

## 추후 발전 방향

### 단기 (현재 데이터·인프라로 가능)
1. **시계열 확장**: 2020·2021·2022·2023·2024 5년치 동일 분석 → DID 분석으로 정책 효과 인과 추정. KOSIS 미충족의료율은 매년 시·군·구 단위 공개.
2. **종속변수 다양화**: 응급실 이용률, 산모·신생아 사망률, 만성질환 입원율 등 outcome 변수와의 상관 확장.
3. **클러스터 K=5 분석 추가**: K=3에서 묶인 "수도권·거점-자원풍부형" 안에 사실 성격이 다른 2~3 유형(부유한 강남 / 노후도심 부산 중구·동구 / 광역시 거점)이 섞임. K=5로 가면 silhouette은 떨어지지만 정책 해석이 정교해짐.
4. **다른 외부 검증 지표**: 응급의료 사망률(시·도), 영아사망률 등 추가.

### 중기 (외부 데이터 통합 필요)
5. **HIRA 시·군·구 단위 데이터 확보** — 가장 강력한 개선. 보건의료빅데이터개방시스템에서 시군구 옵션 데이터를 받으면 WAI/IAI 평탄화 문제 해소. R² 0.5+ 가능.
6. **교통 접근성 통합**: KTDB(국가교통DB) 또는 OSRM(OpenStreetMap 기반 라우팅)으로 가장 가까운 종합병원까지의 자동차 이동시간 산출 → IAI 보강. 박경돈(2012) · Joo·Lee(2022) 선행연구가 채용한 방식.
7. **HASPA(의료기관 회계공시) 통합**: 종합병원 재무·운영 데이터. 자원의 "있음"뿐 아니라 "지속가능성"까지 보는 다층 HRI.
8. **공간 자기상관**(spatial autocorrelation: 지리적으로 가까운 지역이 비슷한 값을 가지는 현상) 분석 — Moran's I, GWR(지리가중회귀). 인접 시·군·구가 의료를 공유하는 효과를 모델에 반영.

### 장기 (학술·정책 기여)
9. **정책 시나리오의 비용-효과 분석**: 시나리오별 ΔHRI를 1대당 비용(전문의 1명, 의원 1개, CT 1대 등)으로 나눠 정책 효율성 비교.
10. **AI 예측 모델**: 인구 추계·재정 데이터로 5년 후 HRI 예측. 의료 소외 가속 지역 사전 식별.
11. **시민 참여 대시보드**: GitHub Pages 지도를 확장해 정책 입안자·기자·시민단체가 직접 시나리오를 조작해볼 수 있는 What-if 도구.
12. **타 분야 확장**: 동일한 PCA → LASSO → 클러스터 → 시뮬레이션 파이프라인은 교육·복지·일자리 등 다른 사회 인프라 지수에도 적용 가능. 본 프로젝트는 일종의 **지역 인프라 평가 프레임워크 템플릿**이 될 수 있다.

## 가능성

본 HRI는 모델 fit이 완벽하지 않지만, 다음 측면에서 **현실적 가치**가 명확하다:

1. **정책 입안자**: 의성·영덕·청송 같은 농촌 의료 취약지대를 정량적으로 식별. 한정된 예산을 어디에 우선 투입할지 데이터 기반 의사결정.
2. **연구자**: 선행연구가 다룬 단일 변수(미충족의료, 관외이용, 치료가능사망)를 통합·횡단면 비교하는 프레임워크.
3. **시민·언론**: 우리 지역의 HRI가 전국 몇 분위인지 한눈에. 의료 격차 담론의 정량 근거.
4. **방법론**: 시도 단위 공급측 데이터와 시·군·구 단위 수요·결과 데이터를 결합한 **하이브리드 다층 분석**의 사례. 데이터 비대칭 환경에서 분석을 포기하지 않는 접근.

마지막으로, 이 프로젝트는 **공개 데이터만으로 약 1주 분량의 작업**으로 도달한 결과다. 추가 데이터(HIRA 시·군·구 데이터)와 시계열만 확보되면 학술 논문 수준으로 충분히 격상 가능하다. GitHub Pages 지도(`https://vashazza.github.io/hri-korea/`)는 결과를 한국 전역 어디서나 보게 만드는 **재현 가능하고 공개된 형태의 정책 도구**다.
